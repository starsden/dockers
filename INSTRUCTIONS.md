# Пошаговая инструкция по подготовке, наполнению и запуску заданий CTF в Docker

Данное руководство описывает архитектуру автономного запуска изолированных стендов для школьных соревнований CTF, структуру шаблонов, правила наполнения контентом и интеграцию с платформой **CTFd**.

---

## 1. Архитектура и принципы работы

1. **Автономность (Offline)**: 
   - Все Docker-образы собираются заранее на этапе подготовки при наличии интернета (или импортируются из архива).
   - Во время проведения соревнований доступ в интернет контейнерам не требуется и блокируется внутренней изолированной сетью `ctf_internal` (`--internal`).
2. **Изоляция и «чистый лист»**:
   - Файлы заданий хранятся на хосте в каталоге `tasks/<id-задания>/content/`.
   - При запуске контейнера каталог монтируется в режиме **только для чтения (`:ro`)**.
   - Любые изменения, файлы, история команд пишутся во временный слой контейнера (overlayfs).
   - При остановке контейнер принудительно удаляется (`docker rm -f`), временный слой стирается. Новый запуск всегда происходит с чистого листа.
3. **Параллельный запуск несколькими участниками**:
   - Каждому запуску участника выделяется персональный блок внешних портов (по умолчанию 10 портов, диапазон `30000–35000`).
   - Имена контейнеров уникальны: `ctf_<task_id>_<session>_<base_port>`.
   - Участники не конфликтуют друг с другом и сканируют/используют только свои порты.
4. **Управление жизненным циклом (TTL)**:
   - Глобальный таймер (по умолчанию 15 минут) настраивается в файле `launcher/config.py`.
   - Участник видит таймер обратного отсчета в веб-интерфейсе и может остановить контейнер вручную по завершении.
   - Фоновый процесс на сервере автоматически удаляет просроченные контейнеры и возвращает порты в пул.

## 2. Структура проекта

```text
.
├── launcher/                      # Сервис управления запуском (на хосте)
│   ├── config.py                  # Главные настройки (IP сервера, TTL, порты)
│   └── server.py                  # HTTP-сервер и API (стандартная библиотека Python)
├── templates/                     # Базовые шаблоны контейнеров
│   ├── web/                       # Шаблон №1: Веб-сервер (Nginx на Alpine)
│   ├── ftp/                       # Шаблон №2: FTP-сервер (vsftpd на Alpine)
│   └── os/                        # Шаблон №3: Легковесная ОС (Alpine + SSH/утилиты)
├── tasks/                         # Каталог заданий
│   ├── 01-ftp-scanner/            # Пример 1: FTP на выделенном порту
│   ├── 02-web-inspection/         # Пример 2: Анализ исходного кода веб-страницы
│   └── 03-web-hidden-port/        # Пример 3: Поиск веб-сервера на нестандартном порту
└── scripts/                       # Вспомогательные скрипты
    ├── build_templates.sh         # Сборка образов шаблонов
    ├── export_offline.sh          # Экспорт образов в tar-архив (для переноса)
    ├── import_offline.sh          # Импорт образов на офлайн-сервере
    ├── start_launcher.sh          # Запуск сервиса управления
    └── cleanup_all.sh             # Экстренная остановка всех заданий
```

## 3. Подготовка и сборка шаблонов

### Вариант А: Сборка на сервере с доступом в Интернет
Выполните одну команду в корне проекта:
```bash
./scripts/build_templates.sh
```
Будут собраны 3 локальных образа:
- `ctf-template-web:latest`
- `ctf-template-ftp:latest`
- `ctf-template-os:latest`

### Вариант Б: Подготовка для полностью изолированного сервера (Air-Gapped)
1. На компьютере с интернетом соберите шаблоны:
   ```bash
   ./scripts/build_templates.sh
   ./scripts/export_offline.sh
   ```
   Появится файл `ctf_templates_offline.tar`.
2. Скопируйте папку проекта и архив `ctf_templates_offline.tar` на сервер соревнований (например, через флешку).
3. На сервере соревнований выполните:
   ```bash
   ./scripts/import_offline.sh
   ```

## 4. Конфигурация параметров сервера

Откройте файл `launcher/config.py` и задайте параметры вашей сети:

```python
# IP-адрес сетевой карты сервера, смотрящей в сеть участников
HOST_IP = "192.168.1.100"

# Порт веб-панели запуска заданий
LAUNCHER_PORT = 8080

# Время жизни контейнера в минутах (по истечении контейнер удалится)
CONTAINER_TTL_MINUTES = 15

# Пул динамических портов хоста
PORT_RANGE_START = 30000
PORT_RANGE_END = 35000

# Размер блока портов на один инстанс
PORTS_PER_INSTANCE = 10
```

## 5. Пошаговое создание нового задания

Чтобы создать новое задание, добавьте папку внутри каталога `tasks/`:

### Шаг 1: Создайте структуру папок
```bash
mkdir -p tasks/my-new-task/content
```

### Шаг 2: Создайте файл конфигурации `tasks/my-new-task/task.json`

#### Для Web-задания (прямой доступ по ссылке):
```json
{
  "id": "my-web-task",
  "title": "Название веб-задания",
  "description": "Описание задания для участника.",
  "template": "web",
  "mode": "direct",
  "service_port": 80,
  "mount_path": "/var/www/html",
  "env": {
    "WEB_PORT": "80"
  }
}
```

#### Для задания со сканированием портов (FTP или нестандартный порт):
```json
{
  "id": "my-scan-task",
  "title": "Название задания на поиск сервиса",
  "description": "Просканируйте выделенные вам 10 портов, найдите скрытый сервис и получите ключ.",
  "template": "web",
  "mode": "scan",
  "port_range_size": 10,
  "service_offset": 5,
  "service_port": 80,
  "mount_path": "/var/www/html"
}
```
*Пояснение параметров:*
- `template`: используемый шаблон (`web`, `ftp` или `os`).
- `mode`: 
  - `"direct"` — веб-интерфейс выведет готовую кликабельную ссылку на сервис;
  - `"scan"` — веб-интерфейс укажет диапазон портов (например, `30010 - 30019`) для сканирования nmap-ом.
- `service_offset`: смещение порта внутри блока (например, при базовом порте 30010 и смещении 5 целевой сервис будет открыт на порту `30015`).
- `mount_path`: точка монтирования файлов задания внутри контейнера (`/var/www/html` для веб-сервера, `/var/ftp/pub` для FTP, `/challenge` для ОС).

### Шаг 3: Наполните папку `content/`
Поместите туда файлы задания:
- Для веб-сервера: `index.html`, изображения, стили, скрытые страницы.
- Для FTP-сервера: файлы архивов, текстовые файлы с ключами (например, `flag.txt`).
- Для ОС: скрипт инициализации `init.sh`, файлы флагов, исполняемые файлы.

## 6. Запуск и управление сервисом

### Запуск сервиса на сервере:
```bash
./scripts/start_launcher.sh
```
Сервис начнет прослушивать `http://0.0.0.0:8080`.

*(Опционально)* Для автозапуска через systemd можно создать `/etc/systemd/system/ctf-launcher.service`:
```ini
[Unit]
Description=CTF Task Launcher Service
After=docker.service
Requires=docker.service

[Service]
Type=simple
User=root
WorkingDirectory=/opt/dockers
ExecStart=/usr/bin/python3 /opt/dockers/launcher/server.py
Restart=always

[Install]
WantedBy=multi-user.target
```

### Экстренная остановка и очистка:
Если соревнование завершилось или требуется сбросить все контейнеры разом:
```bash
./scripts/cleanup_all.sh
```

## 7. Интеграция с платформой CTFd

В существующем контейнере CTFd при создании или редактировании задачи:
1. Перейдите в панель администрирования CTFd -> **Challenges**.
2. В поле **Description (Описание)** вставьте ссылку или iframe на страницу запуска задания:

**Вариант ссылки в отдельной вкладке:**
```markdown
Для выполнения практической части запустите персональный стенд:
[▶ Запустить стенд задания](http://192.168.1.100:8080/task/01-ftp-scanner)
```

**Вариант со встроенным фреймом прямо в модальном окне CTFd:**
```html
<p>Запустите стенд по кнопке ниже:</p>
<iframe src="http://192.168.1.100:8080/task/01-ftp-scanner" 
        width="100%" 
        height="380" 
        style="border: none; border-radius: 8px;">
</iframe>
```

## 8. Разбор готовых примеров заданий

### Пример 1: Поиск и вход на FTP (`tasks/01-ftp-scanner`)
- **Суть задания**: Участник нажимает «Запустить задание». Система выделяет ему 10 портов (например, `30010–30019`).
- **Действия участника**:
  ```bash
  nmap -p 30010-30019 192.168.1.100
  ```
  Обнаруживается открытый порт `30013` (FTP).
  Участник подключается анонимно:
  ```bash
  ftp -p 192.168.1.100 30013
  ```
  Скачивает `flag.txt` и сдает найденный флаг в CTFd.

### Пример 2: Инспекция кода веб-страницы (`tasks/02-web-inspection`)
- **Суть задания**: Участник нажимает «Запустить задание» и получает персональную ссылку на веб-сайт.
- **Действия участника**:
  Открывает страницу в браузере, нажимает `Ctrl+U` (просмотр кода), находит HTML-комментарий разработчика с путем `/s3cr3t_p4th_9921.html`, переходит по нему и забирает флаг.

### Пример 3: Скрытый веб-сервис на нехарактерном порту (`tasks/03-web-hidden-port`)
- **Суть задания**: Участник получает диапазон портов и указание найти веб-сервис.
- **Действия участника**:
  ```bash
  nmap -sV -p 30020-30029 192.168.1.100
  ```
  Nmap определяет, что на порту `30027` работает HTTP (Nginx).
  Участник открывает `http://192.168.1.100:30027` в браузере и видит флаг.
